# 风格指南标题 (h1)

请使用 h1 标题 (`# Heading Title`) 作为主要章节标题。所有 hx 标题都会显示在侧边栏中作为书签。

如果标题不是 h1 标题，侧边栏会出现重复错误，显示页面名称，然后显示 h2 “标题”标题。

---
## 章节标题 (h2)

请使用 h2 标题 (`## Section Heading`)，并在每个新主要部分前加上分隔符 (`---`)。

### 小节标题增加 h 级别 1

请为每个新小节使用 h3 标题 (`### Subsection Heading`)，并为每个新子小节使用 h4 标题 (`#### Sub-Subsection Heading`)。


### 小节 h 级进：2 > 3 > 4

如果 h 级进处理不当，子标题会在侧边栏中混淆。

标题标记应该增加一级或保持不变。

h2 后接 h2 或 h3 是可以的。h3 后接 h3 或 h4 也是可以的。

### 小节错误
h2 后接 h4 会导致问题。侧边栏会将子标题放置在目录中的标题上方。

### 降低 h 级别

这似乎不是一个问题。例如，h4 降至 h3 或 h2 是可以的。

## 格式规范

以下风格是这些 _Imperative_ SRD Markdown 格式的标准。

### 粗体、斜体和分隔符

- 使用双星号 (`**Bold**`) 表示 **粗体** 文本。
- 使用下划线 (`_Italic_`) 表示 _斜体_ 文本。
   - _注：避免使用单星号表示斜体！_
- 使用反斜杠 (`\_`) 来“转义”字符：\_不是斜体\_。
- 使用尖括号 (``` `code` ```) 来制作 `code blocks`。
- 使用三个连字符 (`---`) 来插入水平分隔线。

### 粗体和斜体的规范

旨在坚持以下模式……

#### 粗体标题

描述法术、效果等时使用粗体标题。
- **魔法标题：** 描述。

#### 斜体标题

在变体法术等的“子列表”中使用斜体标题。
- **魔法：** 描述。
  - **_魔法变体 A：_** 描述。
  - **_魔法变体 B：_** 描述。

#### 斜体标题引用

在引用书籍（如 _Mythras Imperative_ 或核心 _Mythras_ 规则集）时，请使用斜体标题。

### 无序列表 / 项目符号

- 无序列表使用连字符。
- 无序列表使用连字符。
  - 使用 2 个空格或一个制表符增加缩进级别。

### 有序列表 / 编号点

1. 编号列表由数字和一个句点组成。
2. 编号列表由数字和一个句点组成。
- 与项目符号混合使用
	- 以及缩进
3. 重新混合数字
   - 以及项目符号

### 标题列表

对于相关子标题的列表，请将标题加粗并加上冒号。
- **示例 1：** 啦，啦，啦……
- **示例 2：** 啦，啦，啦……

### 斜体标题列表

对于相关子标题的列表，请将标题加粗并斜体显示，并加上冒号。
- **_示例 1：_** 啦，啦，啦……
- **_示例 2：_** 啦，啦，啦……

## 表格

为表格提供子标题，以便它们在侧边栏中显示为书签，并从其父部分缩进一级。

~将标题行设为粗体文本。~
将标题行设为粗体实际上会以普通文本呈现它。默认 CSS 已经将该行加粗。

### 表格文本对齐

使用第 2 行进行内容对齐：`:--`、`:-:` 或 `--:`。
这将影响整列。

#### 表格的基本布局

| **列 1** | **列 2** |
| :-: | :-- |
| 1 | alpha |
| 2 | beta |
| 3 | gamma |

### 文本对齐规范

- 对于数字或类似值列表，请使用居中对齐。
- 对于文本句子，请使用左对齐。

#### 对齐示例表

| **数字** | **描述** |
| :-: | :-- |
| 1 | 描述性文本 |
| 2 | 描述性文本 |
| 3 | 描述性文本 |

#### 示例：火势强度表

| **强度** | **示例** | **点燃时间** | **伤害** |
| :-: | :-- | :-: | :-: |
| 1 | 蜡烛 | 1d4 | 1d2 |
| 2 | 火把 | 1d3 | 1d4 |
| 3 | 营火 | 1d2 | 1d6 |
| 4 | 充满房间的大火 | 1d2 | 2d6 |
| 5 | 火山熔岩 | 瞬时 | 3d6 |

## 链接

SRD 中有很多使用链接的地方，这里只涵盖几个主要案例。

### 格式化链接

格式化链接使用括号文本。使用方括号表示可见的链接文本，使用圆括号表示目标 URL：`[Link Text](URL)`。

在这些文档中，最常用的外部链接将是 [Mythras 遭遇生成器](https://mythras.skoll.xyz)。
```
[Mythras Encounter Generator](https://mythras.skoll.xyz)
```

### 外部与内部链接

外部链接通过互联网转到其他页面，并且需要 `http://example.com` URL，默认情况下，它们将_总是_在新的浏览器选项卡中打开。

为了避免多个选项卡使阅读的文档混乱，内部链接和书签使用引用 GitHub 存储库中可见的 markdown 文件的相对 URL 来形成。与新选项卡不同，这些内部链接将快速滚动到链接的部分。

#### 内部链接示例

- **章节链接：** 这些指向主要 (h1) 部分的开头。例如 [战斗](0005_Combat.md) 章节。

  - 链接格式：`[Combat](0005_Combat.md)`

- **小节链接：** 这些指向章节内的标题，引用上述文档，但附加 `?id=`，后跟目标标题。例如 [跳跃攻击](0005_Combat.md?id=leaping-attacks)

  - 链接格式：`[Leaping Attacks](0005_Combat.md?id=leaping-attacks)`

#### 指向小节的外部链接

有时可能需要引用外部文档的已知部分，例如另一个 SRD 中的特定表格。格式与上述小节链接相同，仅使用外部 HTTP URL。

作为一个例子，这里是来自 [Classic Fantasy Imperative SRD](https://cfi-srd.mythras.net/) 的 [英制到公制换算表](https://cfi-srd.mythras.net/#/Appendix_B_Conversion_Tables?id=imperial-weights-and-measures-to-metric-conversion)。

```
[Imperial to Metric conversions table](https://cfi-srd.mythras.net/#/Appendix_B_Conversion_Tables?id=imperial-weights-and-measures-to-metric-conversion)
```

## 魔法和能力列表

以 h2 标题开始一个“整洁”的部分，用于列出可用的法术、能力等；然后为每个列表项使用 h3。

法术和能力通常按魔法类型（民间魔法、神恩等）以单一平面列表形式呈现，但如果列表需要其自己的小节，如流派或教派专精，请适当地增加标题级别。例如，h2 用于神恩奇迹列表，h3 用于教派：密特拉，h4 用于每个密特拉教派奇迹。

特别是在法术的情况下，但在任何使用关键词属性的描述中，请以斜体文本列出它们。

描述性文本和特殊规则使用普通文本。

### 法术列表格式

```
## h2 List name

### List item

_Attributes_

Description text.
```

## 生物数据块
以 h2 标题开始列表的“整洁”部分。生物数据块使用表格，并且在格式和空间要求方面更为复杂。为了清晰起见，避免使用小节并在列表项之间添加分隔符。

每个列出的示例都应具有以下内容……

- **生物标题：** 一个分隔符，后跟生物名称的 h3 标题。

- **MEG 条目：** 指向 [Mythras 遭遇生成器](https://mythras.skoll.xyz/) 上指定生物的外部链接。

- **核心详情：** 生物名称/类型、属性、技能以及任何所需的特殊描述或角色注释。

- **武器详情：** 包含武器名称和以下属性的缩写描述：尺寸（在此处包含力量）、触及范围（在此处包含射程）、伤害、AP/HP 以及任何特殊规则。

- **命中部位与护甲：** 部位表格会根据不同的生物解剖结构而有所不同，但即使对于传统类人生物，也应将其包含在内，作为追踪护甲和伤害的一种方式。

### 生物数据块格式

```
## Bestiary/List Name

Descriptive text. 

---
### Example Creature
[MEG Entry](https://mythras.skoll.xyz/enemy_template/8626/)

| Creature Name | Example Creature  |
| :-- | :-- |
| Key Attributes | STR 11, CON 14, SIZ 11, DEX 11, INT 11, POW 11, CHA 7 |
| Other notes | Values and details | 
```

## 社区勘误

### 错别字和混淆

对作者文本的“清理”编辑应保持最小限度，但错别字和其他错误应直接在线更改，无需任何标记。

### 勘误信息面板

当给定的规则过于模糊、不完整或完全错误时，添加一个可折叠的社区勘误说明。

使用斜体解释问题，并仅对问题标题使用粗斜体 - _没有 h(x) 标题！_ - 以免创建令人困惑的侧边栏条目。

如果添加了替换文本，请将其置于粗斜体的双引号中，前面加上普通权重的斜体 "_社区勘误：_"。

如有必要，其他规则应以普通权重文本呈现。

#### 勘误格式模板

```
<details>

<summary>* Community Errata</summary>

_**Issue Title**_

_Community Errata:_
_**"Replacement text if required."**_

_Explanation text stating how the rule as written causes problems._

</details>
```

#### 勘误示例

<details>

<summary>* 社区勘误</summary>

_**攀爬 (Climb)**_

_社区勘误：_
_**“穿戴的护甲会阻碍攀爬者，程度等于所穿戴护甲点数的平均值。计算方法是将所有部位的穿戴护甲点数总计，然后将该数字除以部位数量。”**_

_书面规则很快会引起问题。穿戴一件 6AP 的护甲会将人类的移动降至 0，这意味着一个只戴钢盔的人会因为负担过重而无法攀爬。这似乎限制得极其不合理，因此建议采用上面建议的编辑版本。如果原作者修改了书面规则，这将进行更新。_

</details>

<details>

<summary>* 社区勘误</summary>

_**步态：行走、奔跑、冲刺**_

_出版版本的 _Mythras Imperative_ 没有针对不同步态移动的明确规则，尽管它们包含在 Mythras 核心规则书中。上面的步态乘数已作为社区勘误的一部分添加。_

_在必要时，将步态视为如下方式应该足够：_

- _快于行走的步态对移动等级应用乘数：奔跑 3 倍，冲刺 5 倍。_

- _在奔跑或冲刺步态期间，角色无法尝试大多数主动动作，如攻击或施法。一些例外包括……_
  - _使用冲锋规则时的攻击。_
  - _使用游击特性的远程武器射击。_
- _作为一般规则，任何允许的动作在奔跑时应被视为难度增加一级，在冲刺时难度增加两级。_

</details>

## 其他警告

### 空行 / 回车

在不同类型的条目之间留一个空行。标题、分隔符、表格等。它们在阅读视图中不会可见，但它们的缺失可能会导致格式问题。

### 粗体或斜体多段文本

每个段落都必须标记为粗体或斜体文本。段落之间的新行会破坏格式，留下孤立的格式标记。

### 国际拼写

倒退和令人遗憾的势力认为合适移除了所有英式拼写，转而采用客观上较弱的美式拼写。请留意英式 -OUR 词汇：_armour_ (盔甲), _favour_ (偏爱) 等。
