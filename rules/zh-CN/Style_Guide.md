# 风格指南标题 (h1)

使用 h1 标题 (`# Heading Title`) 作为主要章节标题。所有 hx 标题都将以书签形式显示在侧边栏中。

如果标题不是 h1 标题，侧边栏将出现重复错误，显示页面名称，然后显示 h2“标题”标题。

---
## 章节标题 (h2)

对每个新的主要部分使用 h2 标题 (`## Section Heading`)，并在其前加上分隔符 (`---`)。

### 子章节标题增加 h 级别 1

对每个新子章节使用 h3 标题 (`### Subsection Heading`)，对每个新的子子章节使用 h4 标题 (`#### Sub-Subsection Heading`)。


### 子章节 h 级数：2 > 3 > 4

如果 h 级数处理不当，子标题在侧边栏中会变得混乱。

标题标记应该每次增加一级或保持不变。

h2 后面跟着 h2 或 h3 是可以的。h3 后面跟着 h3 或 h4 也是可以的。

### 子章节错误
h2 后面跟着 h4 会导致问题。侧边栏将子标题放置在目录中标题上方的某个位置。

### 减小 h 级别

这似乎不是问题。例如 h4 到 h3 或 h2 是可以的。

## 格式约定

以下风格是这些 _命令式_ SRD（Markdown 格式）的规范。

### 粗体、斜体和分隔符

- 使用双星号 (`**Bold**`) 表示 **粗体** 文本。
- 使用下划线 (`_Italic_`) 表示 _斜体_ 文本。
   - _注意：避免使用单星号表示斜体！_
- 使用反斜杠 (`\_`) 来“转义”字符：\_非斜体\_。
- 使用尖括号 (``` `code` ```) 来制作 `code blocks`。
- 使用三个连字符 (`---`) 插入水平分隔线。

### 粗体与斜体的约定

请务必遵守以下模式……

#### 粗体标题

描述法术、效果等时，使用粗体标题。
- **魔法标题：** 描述。

#### 斜体标题

引用变体法术等的“子列表”时，使用斜体标题。
- **魔法：** 描述。
  - **_魔法变体-A：_** 描述。
  - **_魔法变体-B：_** 描述。

#### 斜体标题引用

引用书籍（如 _Mythras Imperative_ 或核心 _Mythras_ 规则集）时，使用斜体标题。

## 列表格式

### 无序列表 / 项目符号

- 无序列表由连字符制成。
- 无序列表由连字符制成。
  - 使用 2 个空格或一个制表符增加缩进级别。

### 有序列表 / 编号点

1. 编号列表由数字和句点制成。
2. 编号列表由数字和句点制成。
- 混合使用项目符号
	- 和缩进
3. 重新混合数字
   - 和项目符号

### 标题列表

对于相关子标题的列表，加粗标题并加上冒号。
- **示例 1：** 啦，啦，啦……
- **示例 2：** 啦，啦，啦……

### 斜体标题列表

对于相关子标题的列表，加粗并倾斜标题并加上冒号。
- **_示例 1：_** 啦，啦，啦……
- **_示例 2：_** 啦，啦，啦……

## 表格

给表格一个子标题，这样它们就会在侧边栏中显示书签，并从其父级章节缩进一级。

~将标题行设为粗体文本。~
将标题行设为粗体实际上会以普通文本形式呈现。默认 CSS 已经将该行加粗。

### 表格文本对齐

使用第 2 行进行内容对齐：`:--`、`:-:` 或 `--:`。
这将影响整列。

#### 表格基本布局

| **第 1 列** | **第 2 列** |
| :-: | :-- |
| 1 | alpha |
| 2 | beta |
| 3 | gamma |

### 文本对齐约定

- 数字或类似值列表使用居中对齐。
- 句子文本使用左对齐。

#### 对齐示例表

| **数字** | **描述** |
| :-: | :-- |
| 1 | 描述性文本 |
| 2 | 描述性文本 |
| 3 | 描述性文本 |

#### 示例：火灾强度表

| **强度** | **示例** | **点燃时间** | **伤害** |
| :-: | :-- | :-: | :-: |
| 1 | 蜡烛 | 1d4 | 1d2 |
| 2 | 火把 | 1d3 | 1d4 |
| 3 | 营火 | 1d2 | 1d6 |
| 4 | 充满房间的火灾 | 1d2 | 2d6 |
| 5 | 火山熔岩 | 瞬时 | 3d6 |

## 链接

SRD 中有许多链接的用途，这里仅涵盖几个主要案例。

### 格式化链接

格式化链接通过方括号文本完成。使用方括号显示可见链接文本，并使用圆括号显示目标 URL：`[Link Text](URL)`。

在这些文档中，最常用的外部链接将是 [Mythras 遭遇生成器](https://mythras.skoll.xyz)。
```
[Mythras Encounter Generator](https://mythras.skoll.xyz)
```

### 外部链接 vs 内部链接

外部链接通过互联网跳转到其他页面，需要 `http://example.com` URL，默认情况下，它们 _总是_ 在新的浏览器选项卡中打开。

为了避免多个选项卡弄乱正在阅读的文档，内部链接和书签由引用 GitHub 存储库中可见的 markdown 文件的相对 URL 形成。与新选项卡不同，这些内部链接将快速滚动到链接的章节。

#### 内部链接示例

- **章节链接：** 这些指向主要 (h1) 章节的开头。例如 [战斗](0005_Combat.md) 章节。

  - 链接格式：`[Combat](0005_Combat.md)`

- **子章节链接：** 这些指向章节内的标题，引用文档如上，但立即追加 `?id=` 后面跟目标标题。例如 [跳跃攻击](0005_Combat.md?id=leaping-attacks)

  - 链接格式：`[Leaping Attacks](0005_Combat.md?id=leaping-attacks)`

#### 指向子章节的外部链接

有时可能需要引用外部文档的已知部分，例如另一个 SRD 中的特定表格。格式与上述子章节链接相同，仅使用外部 HTTP URL。

作为示例，这里是来自 [Classic Fantasy 命令式 SRD](https://cfi-srd.mythras.net/) 的 [英制到公制转换表](https://cfi-srd.mythras.net/#/Appendix_B_Conversion_Tables?id=imperial-weights-and-measures-to-metric-conversion)。

```
[Imperial to Metric conversions table](https://cfi-srd.mythras.net/#/Appendix_B_Conversion_Tables?id=imperial-weights-and-measures-to-metric-conversion)
```

## 魔法与异能列表

使用 h2 标题开启一个“干净”的可用法术、异能等列表部分；然后对每个列表项使用 h3。

法术和异能通常按魔法类型（民俗魔法、神权魔法等）以扁平列表形式呈现，但如果列表需要自己的子章节（如流派或教派专精），请相应地增加标题级别。例如，h2 用于神权奇迹列表，h3 用于教派：密特拉，h4 用于每个密特拉教派奇迹。

特别是在法术描述中，但在任何使用关键字属性的描述中，请使用斜体列出它们。

描述性文本和特殊规则使用普通文本。

### 法术列表格式

```
## h2 List name

### List item

_Attributes_

Description text.
```

## 载具数据块
使用 h2 标题开启一个“干净”的列表部分，然后像往常一样增加分类和列表项的 h 级别。

```

### Category

#### List Item

- **Stat 1:**  [Value]

- **Description:** Descriptive text.
```

## 生物数据块
使用 h2 标题开启列表部分。生物数据块使用表格，在格式和空间要求方面更为复杂。为清楚起见，请避免使用子章节并在列表项之间添加分隔符。

每个列出的示例都应具有以下内容……

- **生物标题：** 一个分隔符，后跟生物名称的 h3 标题。

- **MEG 条目：** 指向 [Mythras 遭遇生成器](https://mythras.skoll.xyz/) 上指定生物的外部链接。

- **核心详情：** 生物名称/类型、属性、技能以及所需的任何特殊描述或角色备注。

- **武器详情：** 简略描述，包含武器名称和以下属性的列：体型（此处包含力）、触及（此处包含射程）、伤害、护甲/生命值以及任何特殊规则。

- **命中部位与护甲：** 部位表格将根据不同的生物解剖结构而有所不同，但即使是传统的类人生物也应包含在内，作为追踪护甲和伤害的一种手段。

### 生物数据块格式

```
## Bestiary/List Name

Descriptive text. 

---
### Example Creature
[MEG Entry](https://mythras.skoll.xyz/enemy_template/8626/)

| Creature Name | Example Creature  |
| :-- | :-- |
| Key 属性 | 力量 11, 体质 14, 体型 11, 敏捷 11, 智力 11, 灵力 11, 魅力 7 |
| Other 备注 | Values and details | 
```

## 社区勘误

### 错别字和混淆

对作者文本进行“清理”的编辑应保持最小化，但错别字和其他错误应直接进行内联更改，无需任何标注。

### 勘误信息面板

当某条规则过于模糊、不完整或完全错误时，请添加一个可折叠的社区勘误说明。

使用斜体解释问题，仅对问题标题使用粗斜体 - _不要使用 h(x) 标题！_ - 以免创建令人困惑的侧边栏条目。

如果添加了替换文本，请将其置于粗斜体双引号中，并在前面加上普通字重的斜体 "_社区勘误：_"。

如有必要，其他规则应以普通字重文本呈现。

#### 勘误格式模板

```
<details>

<summary>* Community Errata</summary>

_**Issue Title**_

_Community Errata:_
_**"Replacement text if required."**_

_Explanation text stating how the rule as written causes problems._

</details>
```

#### 勘误示例

<details>

<summary>* 社区勘误</summary>

_**攀爬**_

_社区勘误：_
_**"穿戴的护甲会阻碍攀爬者，阻碍量等于所穿护甲点数的平均值。通过计算所有部位的所穿护甲点数总和，并除以部位数量来得出此数值。"**_

_原文规定的规则很快会导致问题。穿戴一件 6 护甲的护甲会将人类的移动速率降至 0，这意味着一个只戴钢盔的人会因为负担过重而根本无法攀爬。这似乎限制得极其不合理，因此建议使用上面编辑过的版本。如果原作者修订了原文规则，此内容将进行更新。_

</details>

<details>

<summary>* 社区勘误</summary>

_**步态：步行、快跑、冲刺**_

_出版的 _Mythras Imperative_ 版本对于以不同步态移动没有明确规则，尽管它们在 _Mythras_ 核心规则书中有所涵盖。上述步态乘数已作为社区勘误的一部分添加。_

_在需要时，将步态处理如下应已足够：_

- _快于步行的步态会给移动速率应用乘数：快跑为 3 倍，冲刺为 5 倍。_

- _在快跑或冲刺步态期间，角色不能尝试大多数主动行动，如攻击或施法。一些例外包括……_
  - _使用冲锋规则时的攻击。_
  - _使用游击特性的远程武器射击。_
- _作为一般规则，任何允许的动作在快跑时应被视为高一个等级难度，在冲刺时高两个等级难度。_

</details>

## 其他警告

### 空行 / 回车符

在不同类型的条目之间留一个空行。标题、分隔符、表格等。它们在阅读视图中不会显示，但缺失可能会导致格式问题。

### 粗体或斜体多段文本

每一段都必须标记为粗体或斜体文本。段落之间的新行会破坏格式，留下孤立的格式标记。

### 国际拼写

倒退和令人遗憾的力量认为有必要删除所有英式拼写，转而支持客观上较弱的美式拼写。请留意英式 -OUR 词汇：_armour_、_favour_ 等。
