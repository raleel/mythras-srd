# عنوان راهنمای سبک

از سرتیترهای h1 (`# Heading Title`) برای عنوان اصلی فصل استفاده کنید. تمام سرتیترهای hx در نوار کناری به عنوان نشانک ظاهر خواهند شد.

اگر عنوان یک سرتیتر h1 نباشد، نوار کناری خطای تکراری ایجاد می‌کند که ابتدا صفحه و سپس عنوان h2 را نشان می‌دهد.

---
## سرتیترهای بخش (h2)

برای هر بخش اصلی جدید از سرتیترهای h2 (`## Section Heading`) که با یک جداکننده (`---`) شروع می‌شود، استفاده کنید.

### سرتیترهای زیربخش با افزایش سطح h به میزان ۱

برای هر زیربخش جدید از سرتیترهای h3 (`### Subsection Heading`) و برای هر زیر-زیربخش از سرتیترهای h4 (`#### Sub-Subsection Heading`) استفاده کنید.

### پیشروی h در زیربخش: ۲ > ۳ > ۴

اگر پیشروی h به درستی مدیریت نشود، سرتیترهای فرعی در نوار کناری به هم می‌ریزند.

نشانگر سرتیتر باید یک واحد افزایش یابد یا تغییر نکند.

h2 که به دنبال آن h2 یا h3 بیاید مشکلی ندارد. h3 که به دنبال آن h3 یا h4 بیاید نیز مشکلی ندارد.

### خطاهای زیربخش
h2 که به دنبال آن h4 بیاید باعث بروز مشکل می‌شود. نوار کناری سرتیتر فرعی را جایی بالای سرتیتر اصلی در فهرست مطالب قرار می‌دهد.

### کاهش سطوح h

به نظر نمی‌رسد این مورد مشکلی ایجاد کند. مثلاً h4 به h3 یا h2 مشکلی ندارد.

---
## قراردادهای قالب‌بندی

سبک‌های زیر هنجار این SRDهای *دستوری* (Imperative) در قالب Markdown هستند.

### پررنگ (Bold)، مورب (Italic) و جداکننده‌ها

- از دو ستاره (`**Bold**`) برای متن **پررنگ** استفاده کنید.
- از زیرخط (`_Italic_`) برای متن _مورب_ استفاده کنید.
   - _نکته: از استفاده از یک ستاره برای مورب کردن خودداری کنید!_
- از بک‌اسلش (`\_`) برای 'خنثی کردن' یک کاراکتر استفاده کنید: \_نه مورب\_.
- از گیومه‌های زاویه‌دار (``` `code` ```) برای ایجاد `code blocks` استفاده کنید.
- از سه خط تیره (`---`) برای درج یک خط جداکننده افقی استفاده کنید.

### قراردادها برای پررنگ و مورب

سعی کنید از الگوهای زیر پیروی کنید...

#### عناوین پررنگ

برای توصیف جادوها، افکت‌ها و غیره از عناوین پررنگ استفاده کنید.
- **عنوان جادو:** توصیف.

#### عناوین مورب

برای 'زیر-فهرست‌های' طلسم‌های متغیر و غیره از عناوین مورب استفاده کنید.
- **جادو:** توصیف.
  - **_نوع جادوی الف:_** توصیف.
  - **_نوع جادوی ب:_** توصیف.

#### ارجاعات عنوان مورب

هنگام ارجاع به کتابی مانند _Mythras Imperative_ یا مجموعه قوانین اصلی _Mythras_ از عناوین مورب استفاده کنید.

## جداول

به جداول یک زیر-سرتیتر بدهید تا در نوار کناری نشانک‌گذاری شوند و یک سطح نسبت به بخش والد خود تورفتگی داشته باشند.

~ردیف سرتیتر را به متن پررنگ تبدیل کنید.~
پررنگ کردن ردیف سرتیتر در واقع آن را به متن عادی تبدیل می‌کند. CSS پیش‌فرض آن ردیف را پررنگ می‌کند.

### تراز متن جدول

از ردیف ۲ برای تراز محتوا استفاده کنید: `:--`، `:-:` یا `--:`.
این مورد کل ستون را تحت تأثیر قرار می‌دهد.

#### طرح‌بندی پایه جداول

| **ستون ۱** | **ستون ۲** |
| :-: | :-- |
| ۱ | آلفا |
| ۲ | بتا |
| ۳ | گاما |

### قراردادهای تراز متن

- برای اعداد یا فهرست‌های مقداری مشابه از تراز وسط استفاده کنید.
- برای جملات متنی از تراز چپ استفاده کنید.

#### جدول مثال تراز

| **شماره** | **توصیف** |
| :-: | :-- |
| ۱ | متن توصیفی |
| ۲ | متن توصیفی |
| ۳ | متن توصیفی |

#### مثال: جدول شدت آتش

| **شدت** | **مثال‌ها** | **زمان اشتعال** | **آسیب** |
| :-: | :-- | :-: | :-: |
| ۱ | شمع | 1d4 | 1d2 |
| ۲ | مشعل | 1d3 | 1d4 |
| ۳ | آتش اردوگاه | 1d2 | 1d6 |
| ۴ | حریق اتاق‌پرکن | 1d2 | 2d6 |
| ۵ | گدازه آتشفشانی | آنی | 3d6 |

## لینک‌ها

کاربردهای زیادی برای لینک‌ها در SRD وجود دارد و در اینجا تنها به چند مورد اصلی اشاره می‌شود.

### قالب‌بندی لینک‌ها

قالب‌بندی یک لینک با متن داخل براکت انجام می‌شود. از براکت‌های مربعی برای متن قابل مشاهده لینک و از براکت‌های منحنی برای آدرس مقصد استفاده کنید: `[Link Text](URL)`.

در این اسناد، رایج‌ترین لینک خارجی مورد استفاده [تولیدکننده مواجهه میتراس](https://mythras.skoll.xyz) است.
```
[Mythras Encounter Generator](https://mythras.skoll.xyz)
```

### لینک‌های خارجی در مقابل داخلی

لینک‌های خارجی از طریق اینترنت به صفحات دیگر می‌روند و به یک آدرس `http://example.com` نیاز دارند و به طور پیش‌فرض، _همیشه_ در یک زبانه مرورگر جدید باز می‌شوند.

برای جلوگیری از بهم‌ریختگی زبانه در سند مورد مطالعه، لینک‌های داخلی و نشانک‌ها با آدرس‌های نسبی که به فایل‌های Markdown موجود در مخزن گیت‌هاب اشاره دارند، تشکیل می‌شوند. به جای باز شدن در زبانه جدید، این لینک‌های داخلی به سرعت به بخش پیوند داده شده اسکرول می‌شوند.

#### مثال‌های لینک داخلی

- **لینک‌های فصل:** این‌ها به ابتدای یک بخش اصلی (h1) اشاره دارند. مثلاً فصل [نبرد](0005_Combat.md).

  - فرمت لینک: `[Combat](0005_Combat.md)`

- **لینک‌های زیربخش:** این‌ها به یک سرتیتر درون یک فصل اشاره دارند که مانند بالا به سند ارجاع می‌دهد اما بلافاصله `?id=` و سپس سرتیتر مقصد را اضافه می‌کند. مثلاً [حملات پرشی](0005_Combat.md?id=leaping-attacks)

  - فرمت لینک: `[Leaping Attacks](0005_Combat.md?id=leaping-attacks)`

#### لینک‌های خارجی به زیربخش‌ها

ممکن است مواردی برای ارجاع به یک بخش شناخته شده از یک سند خارجی وجود داشته باشد، مثلاً یک جدول خاص در یک SRD دیگر. قالب‌بندی همانند لینک‌های زیربخش در بالا است، با این تفاوت که از آدرس HTTP خارجی استفاده می‌شود.

به عنوان مثال، در اینجا [جدول تبدیل امپریال به متریک](https://cfi-srd.mythras.net/#/Appendix_B_Conversion_Tables?id=imperial-weights-and-measures-to-metric-conversion) از [Classic Fantasy Imperative SRD](https://cfi-srd.mythras.net/) آمده است.

```
[Imperial to Metric conversions table](https://cfi-srd.mythras.net/#/Appendix_B_Conversion_Tables?id=imperial-weights-and-measures-to-metric-conversion)
```

## فهرست‌های جادو و نیروها

یک بخش 'تمیز' را با یک سرتیتر h2 برای فهرست طلسم‌ها، نیروهای موجود و غیره شروع کنید؛ سپس برای هر آیتم فهرست از h3 استفاده کنید.

طلسم‌ها و نیروها معمولاً در یک فهرست تخت واحد بر اساس نوع جادو (جادوی عامیانه، خداباوری و غیره) ارائه می‌شوند، اما اگر فهرست نیاز به زیربخش‌های خاص خود داشته باشد، مانند تخصص‌های مکتب یا کیش، سطح سرتیتر را به میزان مناسب افزایش دهید. برای مثال، h2 برای فهرست معجزات خداباوری، h3 برای کیش: میتراس، و h4 برای هر معجزه کیش میتراس.

به ویژه در مورد طلسم‌ها، اما در هر توصیفی که از ویژگی‌های کلیدی استفاده می‌کند، آن‌ها را در متن مورب لیست کنید.

متن توصیفی و قوانین ویژه از متن عادی استفاده می‌کنند.

### قالب‌بندی فهرست طلسم‌ها

```
## h2 List name

### List item

_Attributes_

Description text.
```

## بلوک‌های مشخصات وسایل نقلیه
یک بخش 'تمیز' را با یک سرتیتر h2 برای لیست‌ها شروع کنید، سپس سطح h را طبق معمول برای دسته‌ها و آیتم‌های فهرست افزایش دهید.

هر مثال لیست شده، مشخصات و توصیفات را به صورت یک فهرست گلوله‌ای با عناوین پررنگ ارائه می‌دهد.

### قالب‌بندی بلوک مشخصات وسیله نقلیه

```
## h2 List name

### Category

#### List Item

- **Stat 1:**  [Value]

- **Stat 2:**  [Value]

- **Description:** Descriptive text.
```

## بلوک‌های مشخصات موجودات
یک بخش 'تمیز' را با یک سرتیتر h2 برای لیست‌ها شروع کنید. بلوک‌های مشخصات موجودات از جداول استفاده می‌کنند و از نظر قالب‌بندی و نیاز به فضا پیچیده‌تر هستند. برای شفافیت، از زیربخش‌ها خودداری کنید و بین آیتم‌های فهرست جداکننده اضافه کنید.

هر مثال لیست شده باید موارد زیر را داشته باشد...

- **عنوان موجود:** یک جداکننده و به دنبال آن یک سرتیتر h3 برای نام موجود.

- **ورودی MEG:** یک لینک خارجی به موجود مشخص شده در [تولیدکننده مواجهه میتراس](https://mythras.skoll.xyz/).

- **جزئیات اصلی:** نام/نوع موجود، ویژگی‌ها، مهارت‌ها و هر توصیف ویژه یا یادداشت شخصیتی که لازم است.

- **جزئیات سلاح:** توصیفات خلاصه شده با ستون‌هایی برای نام سلاح و ویژگی‌های زیر: اندازه (نیرو را اینجا لحاظ کنید)، دسترسی (برد را اینجا لحاظ کنید)، آسیب، AP/HP، و هر قانون ویژه.

- **نقاط اصابت و زره:** جداول موقعیت بر اساس آناتومی متفاوت موجود تغییر می‌کنند اما باید حتی برای انسان‌نماهای سنتی به عنوان راهی برای ردیابی زره و آسیب گنجانده شوند.

### قالب‌بندی بلوک مشخصات موجودات

```
## Bestiary/List Name

Descriptive text. 

---
### Example Creature
[MEG Entry](https://mythras.skoll.xyz/enemy_template/8626/)

| Creature Name | Example Creature  |
| :-- | :-- |
| Key ویژگی‌ها | قدرت 11, بنیه 14, اندازه 11, چابکی 11, هوش 11, نیروی روحی 11, جذابیت 7 |
| Other یادداشت‌ها | Values and details | 
```

## اصلاحات جامعه (Community Errata)

### غلط‌های تایپی و ابهام

ویرایش‌ها برای 'پاکسازی' متن نویسندگان باید حداقلی باشد، اما غلط‌های تایپی و سایر اشتباهات باید بدون هیچ نشانه‌گذاری به صورت درون‌متنی تغییر کنند.

### پانل‌های اطلاعات اصلاحات

در مواردی که یک قانون خاص بیش از حد مبهم، ناقص یا صرفاً غلط است، یک یادداشت اصلاحات جامعه جمع‌شونده اضافه کنید.

موضوع را با حروف مورب و با استفاده از حروف مورب پررنگ برای عنوان موضوع توضیح دهید - _از سرتیترهای h(x) استفاده نکنید!_ - تا ورودی‌های نوار کناری گیج‌کننده ایجاد نشود.

اگر متن جایگزین اضافه شد، آن را داخل گیومه‌های دوگانه پررنگ و مورب قرار دهید و قبل از آن "_اصلاحات جامعه:_" را با وزن عادی مورب بنویسید.

قوانین اضافی، در صورت نیاز، باید با متن با وزن عادی ارائه شوند.

## هشدارهای متفرقه

### خطوط خالی / بازگشت مکان‌نما

بین انواع مختلف ورودی یک خط خالی بگذارید. سرتیترها، جداکننده‌ها، جداول و غیره. این‌ها در نمای خواندن قابل مشاهده نخواهند بود اما نبودشان می‌تواند باعث مشکلات قالب‌بندی شود.

### متن پررنگ یا مورب چند پاراگرافی

هر پاراگراف باید به عنوان متن پررنگ یا مورب علامت‌گذاری شود. خط جدید بین پاراگراف‌ها قالب‌بندی را می‌شکند و علائم قالب‌بندی یتیم باقی می‌ماند.

### املای بین‌المللی

قدرت‌های واپس‌گرا و تأسف‌بار تصمیم گرفته‌اند تمام املای بریتانیایی را به نفع نسخه‌های عینی ضعیف‌تر آمریکایی حذف کنند. مراقب کلمات بریتانیایی با پسوند -OUR باشید: _armour_، _favour_ و غیره.
