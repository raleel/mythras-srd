# スタイルガイドタイトル (h1)

メインの章のタイトルにはh1見出し (`# Heading Title`) を使用してください。すべてのhx見出しはサイドバーにブックマークとして表示されます。

タイトルがh1見出しでない場合、サイドバーにはページが表示され、その後にh2「タイトル」見出しが表示されるという重複エラーが発生します。

---
## セクション見出し (h2)

新しいメインセクションごとに、区切り線 (`---`) に続くh2見出し (`## Section Heading`) を使用してください。

### サブセクション見出しはhレベルを1上げる

各サブセクションにはh3見出し (`### Subsection Heading`) を、各サブサブセクションにはh4見出し (`#### Sub-Subsection Heading`) を使用してください。

### サブセクションのh階層: 2 > 3 > 4

h階層が正しく処理されない場合、サブ見出しがサイドバーで混同されます。

見出しマーカーは、1つずつ、または増加なしで増やす必要があります。

h2の後にh2またはh3が続くのは問題ありません。h3の後にh3またはh4が続くのも問題ありません。

### サブセクションのエラー
h2の後にh4が続くと問題が発生します。サイドバーでは、サブ見出しが目次の見出しよりも上のどこかに配置されてしまいます。

### hレベルを下げる

これは問題ないようです。例えば、h4からh3またはh2への変更は問題ありません。

## フォーマットの規約

以下のスタイルは、Markdown形式のこれらの _Imperative_ SRDにおける標準です。

### 太字、斜体、区切り線

- **太字**テキストには二重アスタリスク (`**Bold**`) を使用してください。
- _斜体_テキストにはアンダースコア (`_Italic_`) を使用してください。
  - _注: 斜体に単一のアスタリスクを使用しないでください！_
- 文字を「エスケープ」するにはバックスラッシュ (`\_`) を使用してください: \_Not Italic\_。
- `code blocks`を作成するにはアングルクォート (``` `code` ```) を使用してください。
- 水平区切り線を挿入するには3つのハイフン (`---`) を使用してください。

### 太字と斜体の規約

以下のパターンに従うようにしてください...

#### 太字のタイトル

呪文や効果などを説明する際には、太字のタイトルを使用してください。
- **魔法のタイトル:** 説明。

#### 斜体のタイトル

バリエーション呪文などの「サブリスト」には斜体のタイトルを使用してください。
- **魔法:** 説明。
  - **_魔法バリエーションA:_** 説明。
  - **_魔法バリエーションB:_** 説明。

#### 斜体のタイトル参照

_Mythras Imperative_ やコアの _Mythras_ ルールセットのような書籍を参照する場合は、斜体のタイトルを使用してください。

## リストのフォーマット

### 順序なしリスト / 箇条書き

- 順序なしリストはハイフンで作成します。
- 順序なしリストはハイフンで作成します。
  - インデントレベルを2スペースまたはタブで上げます。

### 順序付きリスト / 番号付きポイント

1. 番号付きリストは数字とピリオドで作成します。
2. 番号付きリストは数字とピリオドで作成します。
- 箇条書きと混ぜる
	- そしてインデント
3. 数字を戻す
   - そして箇条書き

### 見出し付きリスト

関連するサブ見出しのリストには、タイトルを太字にしコロンを付けます。
- **例1:** ブラ、ブラ、ブラ...
- **例2:** ブラ、ブラ、ブラ...

### 斜体の見出し付きリスト

関連するサブ見出しのリストには、タイトルを太字かつ斜体にしコロンを付けます。
- **_例1:_** ブラ、ブラ、ブラ...
- **_例2:_** ブラ、ブラ、ブラ...

## テーブル

サイドバーにブックマークとして表示され、親セクションから一段インデントされるように、テーブルにサブヘッダーを付けてください。

~ヘッダー行を太字にしてください。~
ヘッダー行を太字にすると、実際には通常のテキストでレンダリングされます。デフォルトのCSSでその行は太字になっています。

### テーブルのテキスト配置

コンテンツの配置には2行目を使用してください: `:--`、`:-:`、または `--:`。
これは列全体に影響します。

#### テーブルの基本レイアウト

| **列1** | **列2** |
| :-: | :-- |
| 1 | アルファ |
| 2 | ベータ |
| 3 | ガンマ |

### テキスト配置の規約

- 数値や同様の値リストには中央揃えを使用してください。
- 文章のテキストには左揃えを使用してください。

#### 配置の例テーブル

| **番号** | **説明** |
| :-: | :-- |
| 1 | 説明テキスト |
| 2 | 説明テキスト |
| 3 | 説明テキスト |

#### 例: 火力強度テーブル

| **強度** | **例** | **発火までの時間** | **ダメージ** |
| :-: | :-- | :-: | :-: |
| 1 | ろうそく | 1d4 | 1d2 |
| 2 | たいまつ | 1d3 | 1d4 |
| 3 | キャンプファイヤー | 1d2 | 1d6 |
| 4 | 部屋を満たす大火 | 1d2 | 2d6 |
| 5 | 火山の溶岩 | 即時 | 3d6 |

## リンク

SRDではリンクの使用目的が多く、ここでは主要なケースのみをカバーしています。

### リンクのフォーマット

リンクのフォーマットは角括弧で囲まれたテキストで行います。表示されるリンクテキストには角括弧を使用し、宛先URLには丸括弧を使用します: `[Link Text](URL)`。

これらのドキュメントで最も一般的に使用される外部リンクは [Mythras Encounter Generator](https://mythras.skoll.xyz) です。
```
[Mythras Encounter Generator](https://mythras.skoll.xyz)
```

### 外部リンク vs 内部リンク

外部リンクはインターネット経由で他のページに移動し、`http://example.com` URLが必要であり、デフォルトでは_常に_新しいブラウザタブで開きます。

読み取り中のドキュメントに複数のタブが乱雑に表示されないように、内部リンクとブックマークは、GitHubリポジトリに表示されるMarkdownファイルを参照する相対URLで作成されます。新しいタブではなく、これらの内部リンクはリンク先のセクションまで素早くスクロールします。

#### 内部リンクの例

- **章リンク:** これらはメイン (h1) セクションの先頭を指します。例: [戦闘](0005_Combat.md) の章。

  - リンクフォーマット: `[Combat](0005_Combat.md)`

- **サブセクションリンク:** これらは章内の見出しを指し、上記のようにドキュメントを参照しますが、`?id=` を追加し、その直後に宛先見出しを続けます。例: [跳躍攻撃](0005_Combat.md?id=leaping-attacks)

  - リンクフォーマット: `[Leaping Attacks](0005_Combat.md?id=leaping-attacks)`

#### サブセクションへの外部リンク

別のSRDの特定のテーブルなど、外部リンクの既知のセクションを参照する機会があるかもしれません。フォーマットは上記のサブセクションリンクと同じですが、外部のHTTP URLを使用します。

例として、[Classic Fantasy Imperative SRD](https://cfi-srd.mythras.net/) からの [帝国単位からメートル法への換算テーブル](https://cfi-srd.mythras.net/#/Appendix_B_Conversion_Tables?id=imperial-weights-and-measures-to-metric-conversion) を以下に示します。

```
[Imperial to Metric conversions table](https://cfi-srd.mythras.net/#/Appendix_B_Conversion_Tables?id=imperial-weights-and-measures-to-metric-conversion)
```

## 魔法と超能力リスト

利用可能な呪文、能力などのリストにはh2見出しで「クリーンな」セクションを開始し、各リストアイテムにはh3を使用します。

呪文や超能力は通常、魔法の種類（Folk Magic、Theismなど）ごとに単一のフラットなリストとして提示されますが、リストに学校やカルトの専門分野のような独自のサブセクションが必要な場合は、見出しレベルを適切に上げてください。例えば、Theismの奇跡リストにはh2を、カルト: ミトラスにはh3を、そして各ミトラスのカルトの奇跡にはh4を使用します。

特に呪文の場合ですが、キーワード特性を使用する説明では、それらを斜体のテキストでリストしてください。

説明テキストおよび特殊ルールには通常のテキストを使用します。

### 呪文リストのフォーマット

```
## h2 List name

### List item

_Attributes_

Description text.
```

<details>

<summary>例: フォーマットされた呪文リスト (ブロック引用) </summary>

---
> ## 呪文の説明
>
> ### 転回 (Avert)
> _即時、射程あり_
>
> 転回は射程内の別の呪文を打ち消すために使用されます。転回は、「対抗魔法リアクティブアクション」を使用することで、攻撃的な呪文を中和するために反応的に唱えることができます。

</details>

## クリーチャーデータブロック
リスト用にh2見出しで「クリーンな」セクションを開始します。クリーチャーデータブロックはテーブルを使用し、フォーマットやスペース要件の観点からより複雑になります。明確にするため、サブセクションの使用は避け、リストアイテム間に区切り線を追加してください。

リストされている各例には以下を含める必要があります...

- **クリーチャータイトル:** 区切り線に続いて、クリーチャー名のh3ヘッダー。

- **MEGエントリー:** [Mythras Encounter Generator](https://mythras.skoll.xyz/) 上の指定されたクリーチャーへの外部リンク。

- **コア詳細:** クリーチャー名/タイプ、特性値、技能、および必要に応じた特殊な説明やキャラクターの備考。

- **武器詳細:** 武器名の列と、以下の属性の列を持つ要約された説明: サイズ（体格（超能力）をここに含める）、間合い（射程をここに含める）、ダメージ、AP/HP、および特殊ルール。

- **部位判定 & 防具:** 部位テーブルはクリーチャーの解剖学的構造によって異なりますが、防具とダメージを追跡する手段として、伝統的な人型生物の場合でも含める必要があります。

### クリーチャーデータブロックのフォーマット

```
## Bestiary/List Name

Descriptive text. 

---
### Example Creature
[MEG Entry](https://mythras.skoll.xyz/enemy_template/8626/)

| Creature Name | Example Creature  |
| :-- | :-- |
| Key 特性値 | 筋力 11, 体力 14, 体格 11, 敏捷性 11, 知力 11, 霊力 11, 魅力 7 |
| Other 備考 | Values and details | 
```

## コミュニティエラッタ

### タイプミスと混乱

著者のテキストを「整理」するための編集は最小限に留めるべきですが、タイプミスやその他の間違いは、印を付けずにインラインで修正すべきです。

### エラッタ情報パネル

ルールが曖昧すぎる、不完全、または単に間違っている場合は、折りたたみ式のコミュニティエラッタメモを追加してください。

問題のタイトルには_太字の斜体_のみを使用し、_h(x)ヘッダーは使用しないでください！_ これにより、サイドバーの混乱を防ぎます。

置換テキストを追加する場合は、通常の太さの斜体で "_Community Errata:_" を前に置き、太字の斜体の二重引用符内に配置してください。

追加のルールが必要な場合は、通常の太さのテキストで提示してください。

#### エラッタフォーマットテンプレート

```
<details>

<summary>* Community Errata</summary>

_**Issue Title**_

_Community Errata:_
_**"Replacement text if required."**_

_Explanation text stating how the rule as written causes problems._

</details>
```

#### エラッタの例

<details>

<summary>* コミュニティエラッタ</summary>

_**登攀 (Climb)**_

_Community Errata:_
_**"着用している防具は、着用している防具ポイントの平均に等しい量だけ登攀を妨げる。これは、全箇所の着用防具ポイントを合計し、その数値を箇所の数で割ることで求められる。"**_

_書かれているルールはすぐに問題を引き起こします。6APの防具を1つ着用するだけで、人間は移動速度0になり、スチール製のヘルメット以外何も着用していない人間でも登攀するには負担が大きすぎることになります。これは不合理に制限的であるように思われるため、上記のような編集バージョンを提案します。元の著者が書かれているルールを改訂した場合は、これが更新されます。_

</details>

<details>

<summary>* コミュニティエラッタ</summary>

_**歩法: 歩き、走り、全速力**_

_出版された _Mythras Imperative_ には、異なる歩法で移動するための明示的なルールはありませんが、これらは Mythras コア・ルールブックでカバーされています。上記の歩法乗数は、コミュニティエラッタの一部として追加されました。_

_必要な場合は、歩法を次のように扱うだけで十分です:_

- _「歩き」より速い歩法は、移動レートに乗数を適用します: 走りは3倍、全速力は5倍。_

- _「走り」または「全速力」の歩法の間、キャラクターは攻撃や呪文の詠唱といったほとんどの能動的なアクションを試みることはできません。いくつかの例外には以下が含まれます..._
  - _突撃ルールを使用している時の攻撃。_
  - _小競り合い特性を持つ遠隔武器の使用。_
- _一般的なルールとして、許可されたアクションは、「走り」では1等級、「全速力」では2等級難しく実行されるものとして扱うべきです。_


</details>

## その他の警告

### 空行 / キャリッジリターン

異なるタイプのエントリの間には空行を残してください。ヘッダー、区切り線、テーブルなど。これらは閲覧ビューでは表示されませんが、不足しているとフォーマットの問題を引き起こす可能性があります。

### 太字または斜体の複数段落テキスト

各段落は太字または斜体のテキストとしてマークする必要があります。段落間の改行はフォーマットを壊し、孤立したフォーマットマークを残してしまいます。

### 国際的なスペル

退行的で嘆かわしい力によって、客観的に劣る米国版を支持するために、すべての英国スペルが削除されました。英国式の-OUR単語: _armour_、_favour_ などに注意してください。
